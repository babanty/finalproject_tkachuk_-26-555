# ValutaTrade Hub

Учебное консольное приложение для виртуального валютного кошелька и отслеживания курсов. Поддерживает регистрацию, вход, виртуальное пополнение, покупку и продажу валюты, просмотр курсов и оценку портфеля. Пользователи, кошельки, история операций и локальный кэш курсов сохраняются в JSON.

## Демонстрация

[Запись работы приложения в формате asciinema](https://asciinema.org/a/cGgIoUIF1XylxF1f) — полный сценарий с русскими пояснениями, записанный 21.10.2026 в Ubuntu. Продолжительность исходной записи — 4 минуты 17 секунд; размер терминала — 140×35.

Показаны получение реальных курсов CoinGecko и ExchangeRate-API (`update-rates`, `show-rates`), регистрация и вход, пустой портфель, виртуальное пополнение, покупка и продажа BTC, оценка портфеля в USD и EUR, прямой и обратный курс. Отдельно продемонстрированы ошибки недостатка средств и неизвестной валюты, неизменность балансов после ошибок и выход из аккаунта.

## Требования

Python 3.12 и `uv`; команды ниже рассчитаны на Bash (Git Bash в Windows 11 либо Bash в Linux/WSL). В `.python-version` закреплён Python 3.12.15; `uv` может установить его автоматически. Глобальная установка Python и активация `.venv` вручную не нужны. Docker, Kubernetes и отдельная база данных не требуются.

Установите Git и [uv](https://docs.astral.sh/uv/getting-started/installation/), затем откройте новый терминал и проверьте `git --version` и `uv --version`. Для первоначальной загрузки Python и зависимостей нужен интернет. Получите исходники проекта и перейдите в каталог с `pyproject.toml`.

Команды из корня `finalproject_tkachuk_М26-555` в Git Bash:

```bash
uv sync --locked
uv run valutatrade --help
uv run python -m valutatrade_hub --help
uv run python main.py --help
```

`uv sync --locked` восстанавливает окружение по `uv.lock`, включая инструменты разработки, и отказывается незаметно менять несовместимый lock-файл. Повторная команда не удаляет пользовательские данные. Для запуска только с рабочими зависимостями используйте `uv sync --locked --no-dev` и `uv run --no-dev valutatrade`. Имя дистрибутива — `finalproject-tkachuk-m26-555`, импортируемого пакета — `valutatrade_hub`.

## Работа с приложением

Запуск интерактивной сессии:

```bash
uv run valutatrade
```

Внутри приложения:

```text
register --username "Алиса Тест" --password "учебный пароль"
login --username "Алиса Тест" --password "учебный пароль"
show-portfolio
show-portfolio --base EUR
logout
help
exit
```

Регистрация создаёт пустой портфель и не выполняет автоматический вход. Имя пользователя уникально с учётом регистра; пробелы по краям имени удаляются. Пароль должен содержать не менее четырёх символов, пробелы в нём сохраняются. Значения с пробелами заключайте в кавычки. Ошибка команды не завершает интерактивную сессию; `exit`, конец ввода или Ctrl+C завершают приложение.

Вход действует только в текущем процессе. Отдельный вызов `uv run valutatrade login ...` проверяет пароль и завершается: следующий процесс потребует нового входа. Для нескольких команд с одной авторизацией используйте интерактивный режим. Неудачная проверка учётных данных сбрасывает предыдущую сессию.

Общие параметры указываются перед командой. Например, отдельная регистрация с другим каталогом данных:

```bash
uv run valutatrade --data-dir "local data" register --username alice --password 1234
uv run valutatrade --data-dir "local data"
uv run valutatrade --config config.json
```

`register --help` и `login --help` показывают аргументы команд. `show-portfolio` требует входа и принимает `--base`; по умолчанию используется базовая валюта из настроек. Пустой портфель имеет итоговую стоимость 0. При отсутствии нужного курса оценка ненулевого валютного баланса возвращает ошибку.

## Пополнение и сделки

После входа пополните виртуальный баланс USD. Для покупки и продажи нужен свежий локальный кэш курсов:

```text
deposit --amount 10000
buy --currency BTC --amount 0.05
sell --currency BTC --amount 0.01
show-portfolio
```

`deposit` принимает сумму в USD и не требует курса. В `buy` и `sell` параметр `--amount` означает количество единиц выбранной валюты. Покупка списывает USD и начисляет валюту; продажа списывает валюту и зачисляет USD. Покупка создаёт валютный кошелёк автоматически. Продажа требует существующего кошелька и достаточного остатка; отрицательные балансы запрещены. Обмен USD на USD отклоняется: для пополнения используется `deposit`.

Например, при учебном курсе 60000 USD за BTC после этих трёх операций останется 7600 USD и 0.04 BTC. При неизменном курсе итоговая стоимость составляет 10000 USD. Это пример расчёта, а не текущая рыночная котировка. CLI показывает изменения обоих кошельков и стоимость покупки или выручку от продажи.

Баланс и история сохраняются вместе в `portfolios.json` одной атомарной заменой. Каждая успешная операция добавляет запись `transactions`: UUID `id`, `action` (`DEPOSIT`, `BUY`, `SELL`), `currency_code`, `amount`, `rate`, `base` (`USD`), `total`, `timestamp` в UTC. Для пополнения `rate=1`. Ошибки курса, недостаток средств и ошибка записи сохраняют прежние балансы и историю; неудачная покупка не создаёт кошелёк.

Суммы хранятся как `float` без округления до экранной точности. Нечисловые значения, NaN, бесконечность, переполнение и нулевая расчётная стоимость отклоняются. Если сумма настолько мала по сравнению с балансом, что `float` не позволяет изменить остаток, операция также отклоняется.

## Получение курса

Курс доступен без входа, в отдельной команде или интерактивной сессии:

```bash
uv run valutatrade get-rate --from USD --to EUR
uv run valutatrade get-rate --from BTC --to EUR
uv run valutatrade get-rate --from USD --to USD
```

Команда показывает прямой и обратный курс, время обновления в UTC и источник. Для разных валют нужен свежий локальный кэш; курс валюты к самой себе равен 1. Коды валют нечувствительны к регистру и проверяются даже при конвертации в ту же валюту.

## Курсы и оценка портфеля

`rates.json` содержит котировки вида `CURRENCY_USD`: стоимость одной единицы валюты в USD. Кросс-курс рассчитывается как `A_USD / B_USD`; для USD используется 1. Пример структуры (числа иллюстративные, метка времени не означает актуальность рыночных данных):

```json
{
  "pairs": {
    "EUR_USD": {
      "rate": 1.25,
      "updated_at": "2026-10-17T12:00:00Z",
      "source": "example"
    }
  },
  "last_refresh": "2026-10-17T12:00:00Z"
}
```

TTL по умолчанию — 300 секунд, настройка `rates_ttl_seconds` или `VALUTATRADE_RATES_TTL_SECONDS`. Котировка пригодна, если её возраст меньше TTL; ровно на границе она уже устарела. Для кросс-курса проверяются обе котировки, время результата — более раннее из двух. Даты из будущего отклоняются. Общий `last_refresh` не продлевает срок действия отдельных пар.

Прочитанный снимок кэшируется в памяти, но срок свежести проверяется при каждом обращении. Замена файла другим процессом обнаруживается по его метаданным. Все строки портфеля и общий итог вычисляются по одному снимку: отсутствующая или устаревшая нужная котировка приводит к ошибке без частичного итога. Нулевые балансы и остатки в самой базовой валюте не требуют котировок. `show-portfolio` выводит таблицу балансов и стоимости в `--base`.

Если нужная котировка отсутствует, устарела или датирована будущим, `get-rate`, оценка портфеля и сделки делают одну попытку обновления нужных источников: CoinGecko для криптовалют, ExchangeRate для фиата. Свежие пары не вызывают дополнительных запросов. После обновления весь расчёт повторяется по одному снимку; если нужных свежих курсов всё ещё нет, операция завершается ошибкой. Фиктивные резервные цены не используются. HTTP-сессии закрываются при выходе из приложения.

## Обновление и просмотр курсов

Загрузите API-ключи в окружение (см. раздел «Клиенты источников курсов» ниже) и выполните в Git Bash:

```bash
uv run valutatrade update-rates
uv run valutatrade update-rates --source coingecko
uv run valutatrade update-rates --source exchangerate
uv run valutatrade show-rates
uv run valutatrade show-rates --currency BTC --top 2 --base EUR
uv run valutatrade help get-rate
```

Те же команды работают внутри интерактивной сессии без префикса `uv run valutatrade`. Вход не требуется. `update-rates` показывает успешные источники, ошибки, количество обновлённых пар и время последнего обновления. Отказ одного источника не блокирует сохранение другого. Коды выхода одноразовых команд: `0` — успех, `1` — ошибка операции или частичное обновление, `2` — ошибка аргументов. В REPL ошибка отдельной команды не завершает сессию; `quit` — синоним `exit`.

`show-rates` читает только локальный снимок и **никогда не обращается к сети**, в том числе при пустом или устаревшем кэше. `--currency` выбирает исходную валюту; `--top N` оставляет только криптовалюты и сортирует по убыванию цены, `N` — положительное целое. Фильтры применяются совместно. По умолчанию база USD; `--base EUR` пересчитывает строки по кэшированному EUR_USD. Отсутствующая котировка базы — ошибка; просроченная или будущая дата любой зависимости даёт метку `STALE`. Время строки — самое раннее из зависимостей. Такая строка предназначена для просмотра, но не разрешает торговлю по устаревшей цене. Неизвестная валюта отличается от известной, для которой нет котировки. Явный `--currency USD` показывает единицу или обратный курс базы; без фильтра выводятся валюты из снимка. Пустой результат сопровождается подсказкой обновления.

## Запуск парсера по расписанию

Отдельный процесс использует те же `--data-dir` и `--config`, что основной CLI:

```bash
uv run valutatrade-parser --once
uv run valutatrade-parser --once --source coingecko
uv run python -m valutatrade_hub.parser_service --help
uv run valutatrade-parser --interval 300 --fiat-interval 86400
```

`--once` выполняет одно обновление и завершается без ожидания. Без `--once` первый запрос каждого выбранного источника выполняется сразу, затем работают независимые интервалы: CoinGecko — `--interval` либо настройка `update_interval_seconds` (по умолчанию 300 секунд); ExchangeRate — `--fiat-interval` (86400 секунд). `--source` оставляет только указанный источник. Интервал фиата не меняется параметром `--interval`. `--once` и `--interval` взаимоисключающие.

Пауза отсчитывается после завершения попытки, включая неудачную. Запросы последовательны, без перекрытия запусков внутри процесса, без накопления пропущенных запусков и немедленных повторов при ошибках. Ожидаемые ошибки API/хранилища выводятся, цикл продолжается. Ctrl+C или обрабатываемый процессом SIGTERM прерывает ожидание; текущий запрос/сохранение завершается прежде остановки. Сетевой запрос ограничен настройкой таймаута. При остановке обработчики сигналов восстанавливаются и HTTP-сессии закрываются. Это обычный процесс в терминале, не установленная служба; после перезапуска оба источника снова запрашиваются сразу.

Интервалы — настройки приложения, **не гарантия соблюдения квот тарифа**. Перед постоянным запуском сверьте лимиты обоих аккаунтов и при необходимости увеличьте паузы. Не запускайте несколько копий парсера без необходимости. Периодичность фиата отделена от TTL: после 300 секунд фиатный кэш при стандартных настройках помечается устаревшим; торговая команда может сделать дополнительный запрос независимо от расписания. Ручные и автоматические обновления тоже расходуют квоту. Приложение не меняет TTL незаметно и не подменяет время старых котировок ради их «свежести».

## Проверки

```bash
bash scripts/check.sh
```

Скрипт синхронизирует окружение по lock-файлу, запускает Ruff (включая автоисправления и форматирование), затем полный pytest. Тесты используют временные каталоги, фиктивные котировки и подменённый HTTP-транспорт; действующие API-ключи не нужны. Они не заменяют демонстрацию настоящего обращения к API.

## Сборка и самостоятельная установка

В корне исходников, после `uv sync --locked`:

```bash
build_dir="dist/validation-$(date +%Y%m%d-%H%M%S)"
uv build --out-dir "$build_dir"
uv run twine check --strict "$build_dir"/*
wheel="$(realpath "$build_dir/finalproject_tkachuk_m26_555-0.1.0-py3-none-any.whl")"
uv tool install --force --python 3.12 "$wheel"
uv tool dir --bin
```

Используйте новый каталог для каждой проверки, чтобы не смешивать текущие и устаревшие архивы. `uv build` создаёт sdist (`.tar.gz`), затем wheel из него; `twine check` проверяет метаданные и разметку README, ничего не публикуя. Sdist включает тесты, скрипты, `uv.lock`, образец окружения и пустые примеры JSON; wheel — пакет и `default_config.json`, без рабочих данных и тестов.

`uv tool install` устанавливает приложение в отдельное окружение. `--force` заменяет ранее установленную версию этого инструмента, не удаляя пользовательские данные. Добавьте каталог команд в PATH текущего Bash:

```bash
tool_bin="$(uv tool dir --bin)"
if command -v cygpath >/dev/null 2>&1; then
    tool_bin="$(cygpath -u "$tool_bin")"
fi
export PATH="$tool_bin:$PATH"
hash -r
```

Теперь перейдите в отдельный рабочий каталог **вне исходников** и запускайте установленный инструмент без `uv run`:

```bash
mkdir -p "$HOME/valutatrade-work"
cd "$HOME/valutatrade-work"
valutatrade --help
valutatrade-parser --help
valutatrade --data-dir ./data
```

Данные и логи создаются в рабочем каталоге, не рядом с установленным пакетом. `.env` не загружается автоматически: передайте ключи через `export` (см. ниже).

Для офлайн-проверки установленного wheel вернитесь в исходники и выполните:

```bash
tool_home="$(uv tool dir)/finalproject-tkachuk-m26-555"
tool_bin="$(uv tool dir --bin)"
if command -v cygpath >/dev/null 2>&1; then
    tool_home="$(cygpath -u "$tool_home")"
    tool_bin="$(cygpath -u "$tool_bin")"
fi
if [ -f "$tool_home/Scripts/python.exe" ]; then
    installed_python="$tool_home/Scripts/python.exe"
    suffix=".exe"
else
    installed_python="$tool_home/bin/python"
    suffix=""
fi
uv run python scripts/check_installed.py \
    --python "$installed_python" \
    --cli "$tool_bin/valutatrade$suffix" \
    --parser "$tool_bin/valutatrade-parser$suffix"
```

Скрипт запускает именно установленный Python и команды, а не исходники: проверяет происхождение пакета, пакетные настройки, CLI/Parser, сделки по явно фиктивному свежему кэшу, ошибки и сохранение данных. Проверки идут во временном каталоге вне проекта без `PYTHONPATH`; реальные API-ключи исключены из дочернего окружения. Вызов ExchangeRate без ключа проверяет контролируемый отказ до HTTP. После завершения тестовые данные удаляются, установленный пакет не меняется.

Для проверки восстановления окружения распакуйте sdist в новый каталог, выполните там `uv sync --locked` и `bash scripts/check.sh`. Не копируйте `.venv` между каталогами или Windows/Linux: окружение создаётся заново для своей платформы. Wheel разрешает зависимости по ограничениям метаданных; точные версии разработки воспроизводятся через `uv.lock`. Публикация на PyPI не требуется. См. [установку инструментов uv](https://docs.astral.sh/uv/guides/tools/) и [состав дистрибутивов](https://docs.astral.sh/uv/concepts/build-backend/).

## Доменные модели

`core/models.py` содержит `User`, `Wallet` и `Portfolio`. Пароли хранятся как SHA-256 с индивидуальной солью; открытый пароль в модели не сохраняется. Кошельки принимают конечные числовые значения и отклоняют отрицательный баланс, булевы значения и некорректные суммы. Неудачное изменение оставляет прежнее состояние.

`core/currencies.py` определяет `Currency`, `FiatCurrency`, `CryptoCurrency` и `get_currency()`. Поддерживаются USD, EUR, GBP, RUB, BTC, ETH и SOL. Неизвестный код и неверный формат кода имеют разные ошибки. Капитализация в реестре пока не загружена и отображается как `N/A`.

Для оценки `Portfolio` получает функцию `rate_provider(from_code, to_code)`, возвращающую положительный числовой курс. В тестах используются фиксированные учебные котировки. Модели не обращаются к JSON-файлам или API самостоятельно.

## Клиенты источников курсов

`parser_service/api_clients.py` содержит `CoinGeckoClient` и `ExchangeRateApiClient` с общим методом `fetch_rates()`. Каждый возвращает словарь пар вида `BTC_USD` или `EUR_USD`. Все запрошенные валюты одного источника должны пройти проверку: некорректный или неполный ответ вызывает `ApiRequestError` целиком. Таймаут задаётся в конфигурации, автоматических повторов запросов нет. Перенаправления HTTP не выполняются.

CoinGecko использует Demo endpoint `simple/price` и сопоставления BTC→bitcoin, ETH→ethereum, SOL→solana. Ключ `COINGECKO_API_KEY` передаётся заголовком `x-cg-demo-api-key`. Без него допускается одна попытка обычного запроса; доступ в этом режиме не гарантируется. ExchangeRate-API требует `EXCHANGERATE_API_KEY` и читает `conversion_rates` стандартного v6-ответа с базой USD. Значения USD→EUR/GBP/RUB инвертируются: например, `0.927` превращается в `EUR_USD = 1 / 0.927`.

`ParserConfig` читает ключи из окружения при создании; `repr` их не содержит. `.env` автоматически не загружается. `.env.example` содержит только пустые `EXCHANGERATE_API_KEY` и `COINGECKO_API_KEY`. Создайте собственный `.env` на его основе, не перезаписывая существующий, и заполните ключи из кабинетов поставщиков. Не добавляйте `.env` в Git и не показывайте при записи демонстрации. Для запуска из исходников:

```bash
uv run --env-file .env valutatrade update-rates
uv run --env-file .env valutatrade
```

Для установленной команды либо без сохранения ключей на диск введите их скрыто в текущем Bash:

```bash
read -r -s -p "ExchangeRate API key: " EXCHANGERATE_API_KEY; printf '\n'
read -r -s -p "CoinGecko Demo API key: " COINGECKO_API_KEY; printf '\n'
export EXCHANGERATE_API_KEY COINGECKO_API_KEY
valutatrade update-rates
```

Команды ввода не содержат значений ключей в истории shell. Не используйте `echo` для проверки секретов. После работы при необходимости выполните `unset EXCHANGERATE_API_KEY COINGECKO_API_KEY`. Для входа используйте только учебные пароли: командный интерфейс и SHA-256 с солью реализованы для задания, не для защиты настоящих финансовых учётных данных.

`ParserConfig.from_settings(settings)` использует общие пути данных и таймаут Core. Клиент не записывает JSON и не изменяет кошельки. После полного успешного ответа `last_metadata` содержит UTC-время получения, длительность в миллисекундах, HTTP-статус и метаданные пар. Время котировки поставщика сохраняется отдельно как `provider_updated_at`, если оно присутствует; отсутствующее время не выдумывается. Перед каждой попыткой прежние метаданные очищаются. Сессии, созданные клиентом, освобождаются методом `close()`; переданными извне сессиями управляет вызывающий код.

Контракты: [CoinGecko Demo](https://docs.coingecko.com/demo/reference/simple-price), [ExchangeRate-API Standard](https://www.exchangerate-api.com/docs/standard-requests). Примеры ответов для офлайн-проверок находятся в `tests/fixtures/api/`; тесты запрещают реальные HTTP-запросы и используют подменённый транспорт.

## Снимок и история курсов

`RatesUpdater(RateStorage(database), clients).run_update(source=None)` последовательно получает котировки из словаря клиентов с ключами `coingecko` и `exchangerate`. Параметр `source` выбирает один источник. Возвращается `UpdateResult`: `success_sources`, `errors`, `updated_count`, `last_refresh`. Успех источника означает корректный ответ, а `updated_count` — число добавленных или обновлённых пар снимка, включая восстановленные измерения. Повторное или запоздавшее измерение может дать нулевой счётчик обновлённых пар.

`exchange_rates.json` хранит историю измерений с идентификатором `FROM_USD_<UTC-время получения>`, курсом, источником и метаданными запроса. `rates.json` содержит последние курсы для Core. Повторная запись того же измерения не создаёт дубликат; другое содержимое с тем же идентификатором вызывает `StorageError`. Время нормализуется в UTC с микросекундами. Более старое или равное время не заменяет текущую пару. При отказе одного API котировки другого сохраняются, а время старых пар остаётся прежним. При полном отказе источников файлы не изменяются.

Сетевые запросы выполняются до межпроцессной блокировки. Под общей с Core блокировкой документы перечитываются, история дополняется и записывается первой, снимок — вторым. Каждый файл заменяется атомарно, но общая замена двух файлов не является одной транзакцией. Если снимок не удалось сохранить, обновление возвращает ошибку; уже записанная история сохраняется. Следующее успешное обновление восстанавливает недостающие изменения автоматически. Метод `RateStorage.rebuild_cache_from_history()` позволяет явно восстановить снимок, в том числе отсутствующий или повреждённый, из корректной истории. Повреждённая история не затирается. Корректные пары, существующие только в старом снимке, сохраняются; при утрате самого снимка восстановимы только записанные в историю измерения.

Перед запуском обновлений `configure_parser_logging(settings)` настраивает отдельный `logs/parser.log` с общей политикой ротации. JSON-записи содержат результат обновления, ошибки источников и изменения цены (`before`, `after`, `delta`) только после успешного сохранения. Журнал диагностический: его отказ не меняет результат записи курсов.

## Журнал действий

При запуске приложения журнал настраивается в `logs/actions.log` рядом с каталогом данных. `deposit`, `buy` и `sell` записываются в формате JSON Lines: одна операция — одна строка с UTC-временем, пользователем, валютой, суммой, курсом, расчётной валютой и результатом `OK` или `ERROR`. Для успешной операции также сохраняются UUID, стоимость и балансы до и после; для ошибки — её тип и безопасное сообщение. Справка и отдельная команда `exit` журнал не создают.

Успех записывается только после сохранения портфеля. Неуспешная запись данных получает `ERROR`, а исходное исключение передаётся в CLI. Пароли, хеши, соли, полные аргументы команд и URL запросов в журнал не передаются; известные API-ключи из окружения маскируются в сообщениях. Регистрация и вход не журналируются.

Параметры JSON-конфига: `log_dir` (по умолчанию соседний с данными `logs`), `log_level` (`INFO`), `log_format` (`json`), `log_max_bytes` (`1048576`), `log_backup_count` (`3`). Они также задаются переменными `VALUTATRADE_LOG_DIR`, `VALUTATRADE_LOG_LEVEL`, `VALUTATRADE_LOG_FORMAT`, `VALUTATRADE_LOG_MAX_BYTES`, `VALUTATRADE_LOG_BACKUP_COUNT`. При ротации остаются `actions.log` и до трёх архивов `actions.log.1`–`actions.log.3`. Все события действий имеют уровень `INFO`; уровень `WARNING` и выше отключает их запись.

Журнал является диагностическим: ошибка его записи после запуска не отменяет сохранённую сделку. Полная история успешных операций хранится в `portfolios.json`. Логи и архивы не включаются в Git.

## Настройки и хранение данных

`SettingsLoader` загружает настройки один раз за процесс. Приоритет от меньшего к большему: пакетный `default_config.json`, явно указанный JSON-конфиг, переменные `VALUTATRADE_*`, словарь `overrides` (в том числе параметр CLI `--data-dir`). Значения проверяются; ошибочная настройка не заменяется молча значением по умолчанию. Повторный вызов конструктора возвращает существующий экземпляр. Явно передать другую конфигурацию после загрузки нельзя.

Пример программного API:

```python
from valutatrade_hub.infra.database import DatabaseManager
from valutatrade_hub.infra.settings import SettingsLoader

settings = SettingsLoader(overrides={"data_dir": "local data"})
database = DatabaseManager(settings)
database.initialize()
```

Пример пользовательского JSON-конфига для `SettingsLoader("config.json")`:

```json
{
  "data_dir": "local data",
  "rates_ttl_seconds": 300,
  "lock_timeout_seconds": 5
}
```

Пути разрешаются относительно текущего рабочего каталога. По умолчанию данные находятся в `./data`, логи — в соседнем `./logs`. Полный список настроек ниже; имя переменной окружения — `VALUTATRADE_` плюс имя настройки в верхнем регистре, например `VALUTATRADE_RATES_TTL_SECONDS`.

| Настройка | По умолчанию | Назначение |
|---|---|---|
| `data_dir` | `data` | Каталог JSON |
| `log_dir` | `null` | `logs` рядом с каталогом данных |
| `rates_ttl_seconds` | `300` | Срок свежести каждой пары |
| `base_currency` | `USD` | База оценки портфеля |
| `request_timeout_seconds` | `10` | Таймаут HTTP |
| `update_interval_seconds` | `300` | Интервал CoinGecko для парсера |
| `log_level` | `INFO` | Уровень диагностических событий |
| `log_format` | `json` | Формат журнала |
| `log_max_bytes` | `1048576` | Порог ротации |
| `log_backup_count` | `3` | Число архивов каждого журнала |
| `lock_timeout_seconds` | `5` | Ожидание файловой блокировки |

Не задавайте необязательные переменные пустыми строками: чтобы применились значения по умолчанию, оставьте переменные незаданными. Отдельный интервал фиата задаётся параметром `--fiat-interval`, а не `update_interval_seconds`.

Сам `SettingsLoader` не ищет `.env`; для передачи его содержимого в окружение можно использовать `uv run --env-file .env ...`.

CLI вызывает `initialize()` при запуске сессии или пользовательской операции: создаются `users.json`, `portfolios.json`, `rates.json` и `exchange_rates.json`. Повторная инициализация сохраняет существующие данные. Пустые образцы форматов находятся в `data/examples/`; настоящие данные игнорируются Git. Конструкторы, импорт пакета, справка и отдельная команда `exit` runtime-файлов не создают.

`DatabaseManager` предоставляет `load_users()`, `get_user()`, `find_user()`, `get_portfolio()`, `save_account()` и `update_portfolio()`. Изменение кошельков выполняется через callback в `update_portfolio()`: актуальный файл читается под межпроцессной блокировкой, а результат сохраняется только после успешной валидации. JSON-файл заменяется атомарно после записи и fsync закрытого временного файла. Повреждённый JSON, неверные схемы, таймаут блокировки и ошибка записи вызывают `StorageError`.

Пользователь и его портфель сохраняются двумя отдельными атомарными заменами. При обычной ошибке второй записи первая откатывается. Это не гарантирует общую транзакцию двух файлов при отключении питания; обнаруженная рассогласованность требует восстановления и не подменяется пустыми данными.
