# ValutaTrade Hub

Учебное консольное приложение для виртуального валютного кошелька и отслеживания курсов. Реализация ведётся последовательно. Доступны доменные модели, иерархия валют, настройки и JSON-хранилище; CLI пока показывает справку. Пользовательские команды будут подключены на следующих этапах.

## Требования

Windows 11, Git Bash и `uv`. Проект фиксирует Python 3.12 в `.python-version`; `uv` может установить его автоматически. Глобальная установка Python и активация `.venv` вручную не нужны.

Команды из корня `finalproject_tkachuk_М26-555` в Git Bash:

```bash
uv sync --locked
uv run valutatrade --help
uv run python -m valutatrade_hub --help
uv run python main.py --help
```

## Проверки

```bash
bash scripts/check.sh
uv build
```

Перед каждым локальным Git-коммитом выполняются Ruff и полный набор тестов. Реальные JSON-данные приложения, логи и `.venv` не отслеживаются Git. Инструкции по кошельку, настройкам курсов и Parser Service будут дополнены на соответствующих этапах.

## Доменные модели

`core/models.py` содержит `User`, `Wallet` и `Portfolio`. Пароли хранятся как SHA-256 с индивидуальной солью; открытый пароль в модели не сохраняется. Кошельки принимают конечные числовые значения и отклоняют отрицательный баланс, булевы значения и некорректные суммы. Неудачное изменение оставляет прежнее состояние.

`core/currencies.py` определяет `Currency`, `FiatCurrency`, `CryptoCurrency` и `get_currency()`. Поддерживаются USD, EUR, GBP, RUB, BTC, ETH и SOL. Неизвестный код и неверный формат кода имеют разные ошибки. Капитализация в реестре пока не загружена и отображается как `N/A`.

Для оценки `Portfolio` получает функцию `rate_provider(from_code, to_code)`, возвращающую положительный числовой курс. В текущих тестах используются фиксированные учебные котировки. Модели не обращаются к JSON-файлам или API самостоятельно. Подробности — в [описании архитектуры](docs/architecture.md).

## Настройки и хранение данных

`SettingsLoader` загружает настройки один раз за процесс. Приоритет от меньшего к большему: пакетный `default_config.json`, явно указанный JSON-конфиг, переменные `VALUTATRADE_*`, словарь `overrides` для будущих CLI-параметров. Значения проверяются; ошибочная настройка не заменяется молча значением по умолчанию. Повторный вызов конструктора возвращает существующий экземпляр. Явно передать другую конфигурацию после загрузки нельзя.

Пример программного API (CLI для этих операций появится на следующем этапе):

```python
from valutatrade_hub.infra.database import DatabaseManager
from valutatrade_hub.infra.settings import SettingsLoader

settings = SettingsLoader(overrides={"data_dir": "local data"})
database = DatabaseManager(settings)
database.initialize()
```

Пример пользовательского JSON-конфига для `SettingsLoader("config.json")`:

```json
{
  "data_dir": "local data",
  "rates_ttl_seconds": 300,
  "lock_timeout_seconds": 5
}
```

Пути разрешаются относительно текущего рабочего каталога. По умолчанию данные находятся в `./data`, логи — в соседнем `./logs`. Путь можно изменить через `VALUTATRADE_DATA_DIR`, а логи — через `VALUTATRADE_LOG_DIR`. TTL задаётся `VALUTATRADE_RATES_TTL_SECONDS`. Полный список переменных и исходные значения показаны в `.env.example`.

Сам `SettingsLoader` не ищет `.env`; для передачи его содержимого в окружение можно использовать `uv run --env-file .env ...`. Локальные API-ключи потребуются на этапе подключения Parser Service.

Только явный `initialize()` создаёт `users.json`, `portfolios.json`, `rates.json` и `exchange_rates.json`. Повторная инициализация сохраняет существующие данные. Пустые образцы форматов находятся в `data/examples/`; настоящие данные игнорируются Git. Конструкторы, импорт пакета и `--help` runtime-файлов не создают.

`DatabaseManager` предоставляет `load_users()`, `get_user()`, `find_user()`, `get_portfolio()`, `save_account()` и `update_portfolio()`. Изменение кошельков выполняется через callback в `update_portfolio()`: актуальный файл читается под межпроцессной блокировкой, а результат сохраняется только после успешной валидации. JSON-файл заменяется атомарно после записи и fsync закрытого временного файла. Повреждённый JSON, неверные схемы, таймаут блокировки и ошибка записи вызывают `StorageError`.

Пользователь и его портфель сохраняются двумя отдельными атомарными заменами. При обычной ошибке второй записи первая откатывается. Это не гарантирует общую транзакцию двух файлов при отключении питания; обнаруженная рассогласованность требует восстановления и не подменяется пустыми данными.
